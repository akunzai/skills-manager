# Self-update delegates to the package manager, except Scoop

When a package manager owns the running binary, `skills self-update` never downloads a release and never replaces the binary itself. For Homebrew and mise, it runs that package manager's upgrade command on the user's terminal, once the user confirms or passes `--yes`, and exits with 2 if the command fails. For Scoop, it only names the command. It also only names the command under `--json`, which keeps stdout for one document, and under a pinned `--version`, which the upgrade command cannot install. It does not ask GitHub first: the package manager decides whether there is anything to upgrade, and a tap formula can trail a GitHub release.

Running the package manager's command is not self-updating. [Homebrew's policy](https://docs.brew.sh/Acceptable-Formulae) is that "Software that updates itself conflicts with Homebrew's version and upgrade management", and the binary is still replaced only by `brew upgrade`. [`mise upgrade`](https://mise.jdx.dev/cli/upgrade.html) installs the new version beside the running one and removes the old one only after a grace period. It also keeps the version range the user's mise config requests, so a pinned release stays pinned: `self-update` reports what `mise upgrade` did rather than adding `--bump`, which would rewrite the user's config.

Scoop is excluded because it cannot work. `scoop update` skips an app with a process running from its directory, printing "Running process detected, skip updating." (`test_running_process` in [`lib/install.ps1`](https://github.com/ScoopInstaller/Scoop/blob/master/lib/install.ps1), called from [`libexec/scoop-update.ps1`](https://github.com/ScoopInstaller/Scoop/blob/master/libexec/scoop-update.ps1)), and `self-update` is such a process. Launching a detached `scoop update` and exiting was rejected: it is fragile, and the user would never see whether the upgrade succeeded.

Running the command without asking was rejected for the same reason ADR-0006 gives: replacing the binary is a consequential change the user must ask for. A terminal prompt, or `--yes`, is that request. Without a terminal and without `--yes`, `self-update` keeps the refusal, exit 1, naming the command. Declining the question is backing out before anything ran, so it says the operation was cancelled and exits 0 (ADR-0002).

This narrows the refusal introduced for #211; it does not change ADR-0006. The daily notice and `--check` still name the package manager's own command, which works whether or not it is run through `self-update`.
